$ wincode --help
Build, sign and upload Flutter iOS apps from Windows.

Usage: wincode <command> [arguments]

Global options:
-h, --help             Print this usage information.
    --config=<file>    The app's settings: bundle ID, team ID, profile, entitlements, CI workflow, output folder. No secrets.
                       (defaults to "wincode.yaml")
    --app=<name>       The app that the command works on, when wincode.yaml has an apps: map. Needed when it has several (ADR-0014).
    --all              Run preflight or doctor for every app in wincode.yaml, one after another, and print a summary table. Refused by commands that write.
    --json             Print one JSON object on stdout when the command ends, and the messages on stderr.
    --redact           Hide the bundle ID and team ID in everything printed. Always on when the CI variable is set.
    --verbose          Also print each step, external command and HTTP request, with secrets redacted.
    --dry-run          Send, write and run nothing, and print what would be done.

Available commands:
  build       Build the unsigned IPA on the app's macOS runner (GitHub Actions) and download it.
  doctor      Check the setup, or a Mach-O binary against the SDK or a reference build.
  init        Write wincode.yaml for the Flutter project in this folder.
  preflight   Check the signed IPA and App Store Connect before an upload. Read-only.
  sign        Sign the IPA for the App Store with zsign in WSL2, and check the result (ADR-0013, phase 3a).
  status      Show the state of the app's latest uploads in App Store Connect. Read-only.
  upload      Upload the signed IPA to App Store Connect and wait for its processing (ADR-0013, phase 4). The only command that writes to Apple.

Run "wincode help <command>" for more information about a command.
Global options go before or after the command.

Exit codes:
  0   done
  1   failed: a check found a problem, an input is wrong, or Apple or GitHub refused the work
  64  usage error, or not implemented yet
  65  upload: Apple took the IPA and then failed its processing
  69  a tool, the SDK or the network is missing
  70  a bug in winCode
  75  upload: Apple had not finished processing within --timeout
  77  Apple or GitHub refused the credentials
  78  wincode.yaml or an environment variable is wrong

$ wincode help doctor
Check the setup, or a Mach-O binary against the SDK or a reference build.

Without options, doctor checks the setup of the app in wincode.yaml and sends nothing: that the file loads, and that the app's App Store Connect key is where its credentials say (a folder with one AuthKey_<Key ID>.p8 and an issuer-id, outside git working trees and OneDrive). With --sign, it also checks WSL2, the pinned zsign 1.9.0 (f6158be9), whose build commands it prints, and where the distribution key is; the first check that finds zsign records its SHA-256 outside the repository, and wincode sign runs only that binary. To check a binary, give --binary and at least one of --sdk and --reference.

Usage: wincode doctor [arguments]
-h, --help                         Print this usage information.
    --binary=<Mach-O file>         The binary to check, such as Payload/Runner.app/Runner.
    --sdk=<iPhoneOS.sdk folder>    Check the binary against the SDK's text stubs. Fails on a library or binding that its minimum OS lacks.
    --reference=<Mach-O file>      List how the binary differs from a reference build, such as an Xcode-built copy. This does not fail.
    --sign                         Also check what wincode sign needs: WSL2 version 2, the pinned zsign and its recorded SHA-256 (recorded by the first check that finds it), and where the distribution key is.

Run "wincode help" to see global options.

$ wincode help init
Write wincode.yaml for the Flutter project in this folder.

init reads ios/Runner.xcodeproj for the bundle ID and the entitlements, and the .mobileprovision files of a folder that you name, shows what it found, and asks you to confirm each value. It never writes a key or the key folder (WINCODE_ASC_KEY_DIR), and it never edits .gitignore.

It asks only at a terminal. In CI (the CI variable), with --yes or with --json it asks nothing: give every field as an option, or --yes to accept what it found. Without --force it does not replace a wincode.yaml.

With --app <name> it adds that app to a file of apps (or starts one), or updates its entry in place, keeping the comments and the layout of the rest, after showing the changes and asking you to confirm (--yes where it cannot ask); a value that the entry already has is replaced only with --force. On a flat wincode.yaml, --app moves the file under apps: as the app that it describes, keeps the original as wincode.yaml.bak, and needs a yes too (ADR-0014). After a write, init loads the file again and puts the old one back if it does not load.

Usage: wincode init [arguments]
-h, --help                    Print this usage information.
    --bundle-id=<id>          The app's bundle ID. Default: read from ios/Runner.xcodeproj.
    --team-id=<id>            The team ID (10 capital letters and digits). Default: from the profile or the Xcode project.
    --profile=<file>          The App Store profile (.mobileprovision). It must lie outside git working trees, or be ignored by git.
    --profile-dir=<folder>    A folder to list the App Store profiles of this app in. Nothing else is searched.
    --entitlements=<file>     The .entitlements file. Default: the one of the Xcode project.
    --workflow-ref=<ref>      The CI workflow for wincode build: <owner>/<repository>/.github/workflows/<file>@<branch or tag>.
    --output=<folder>         Where the IPAs go (default build/wincode).
    --flavor=<name>           The Flutter flavor of the app: read the Release-<name> configuration of the Xcode project, the App Store build, and record the flavor. Can be combined with --configuration.
    --configuration=<name>    Read exactly this build configuration of the Xcode project, such as Release-demo, and do not compare Debug and Profile with it. With --flavor it overrides the default Release-<name>.
    --credentials=<name>      The credentials reference of the app: the folder of your keys folder that holds its keys. Required for an app of a file of apps.
    --workflow                Copy the reference workflow to .github/workflows/wincode-ios.yml. It never replaces a file.
-y, --yes                     Ask nothing: accept what init found.
    --force                   Replace an existing wincode.yaml.

Run "wincode help" to see global options.

$ wincode help preflight
Check the signed IPA and App Store Connect before an upload. Read-only.

On this PC: the API key and the profile lie outside git working trees, the profile in wincode.yaml, and the IPA (signed.ipa in the output folder by default) with its bundle ID, version, build number and signature. In App Store Connect, with GET requests only: the key works, the app record exists, the build number is above every existing build's, and the App ID has an active App Store profile.

The API key is read from the folder that WINCODE_ASC_KEY_DIR names: AuthKey_<Key ID>.p8 and issuer-id.

Usage: wincode preflight [<signed .ipa>]
-h, --help    Print this usage information.

Run "wincode help" to see global options.

$ wincode help sign
Sign the IPA for the App Store with zsign in WSL2, and check the result (ADR-0013, phase 3a).

Before zsign runs: the unsigned IPA (unsigned.ipa in the output folder by default) holds the app of wincode.yaml in Payload/ only, without extensions; the profile is an App Store profile of the team and app, not expired; the distribution key, found through the app's credentials (or WINCODE_DIST_KEY for a file without them), is an unencrypted RSA PEM key whose certificate is in the profile, an Apple Distribution certificate of the team that has not expired and that App Store Connect still lists; and the entitlements are allowed by the profile. zsign then reads the key in place through wslpath and never gets a password. After it: every signature is checked and preflight's local checks run, and only then is the IPA moved to signed.ipa in the output folder. Its temporary files there are deleted whatever happens.

Usage: wincode sign [<unsigned .ipa>]
-h, --help           Print this usage information.
    --offline        Do not ask App Store Connect whether the certificate is still a valid distribution certificate. The run warns that it was not asked.
    --verify-only    Sign nothing: check the signatures of a signed IPA (signed.ipa in the output folder by default) against the profile, the certificate that signed it (one of the profile's, and listed in App Store Connect unless --offline) and the entitlements, then run preflight's local checks. Needs no WSL2 and no private key.

Run "wincode help" to see global options.

$ wincode help upload
Upload the signed IPA to App Store Connect and wait for its processing (ADR-0013, phase 4). The only command that writes to Apple.

Every check runs first, and one that fails stops the command before a single upload request: the IPA (signed.ipa in the output folder by default) must be signed, its signatures must verify against the profile in wincode.yaml and a distribution certificate that App Store Connect lists, and its build number must be above every build the app has. Then it prints what it will send and asks you to type the name of the app (the bundle ID for a file without names); --yes skips that, and without a terminal, in CI or with --json, --yes is required.

It then creates the build upload, sends the file in the parts that Apple names, marks it uploaded with its MD5, and asks for the state every 30 s until the build is valid or failed, or --timeout has passed. A build number that Apple has taken stays used, so nothing that creates an upload is repeated; the parts and the questions about the state are, with a short backoff. The token, the key and the signed links of the parts are never printed.

--dry-run sends nothing: it checks what needs no network, and prints the plan and the requests.

Exit codes: 0 valid, 1 a check failed or Apple refused, 65 Apple failed the processing, 69 no network, 75 not finished within --timeout, 77 Apple refused the key.

Usage: wincode upload [--ipa <file>] [<signed .ipa>]
-h, --help                 Print this usage information.
    --ipa=<file>           The signed IPA to upload. Default: signed.ipa in the output folder of the app.
    --timeout=<minutes>    How long to wait for Apple's processing result after the upload: a number of minutes, such as 20, or of seconds with an s, such as 90s. When it passes, the exit code is 75 and the upload is not lost.
                           (defaults to "20")
-y, --yes                  Do not ask for the name of the app. Needed in CI, with --json and without a terminal.

Run "wincode help" to see global options.

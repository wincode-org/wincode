$ wincode --help
Build, sign and upload Flutter iOS apps from Windows.

Usage: wincode <command> [arguments]

Global options:
-h, --help             Print this usage information.
    --config=<file>    The app's settings: bundle ID, team ID, profile, entitlements, CI workflow, output folder. No secrets.
                       (defaults to "wincode.yaml")
    --json             Print one JSON object on stdout when the command ends, and the messages on stderr.
    --redact           Hide the bundle ID and team ID in everything printed. Always on when the CI variable is set.
    --verbose          Also print each step, external command and HTTP request, with secrets redacted.
    --dry-run          Send, write and run nothing, and print what would be done.

Available commands:
  build       Build the unsigned IPA on the app's macOS runner (GitHub Actions) and download it.
  doctor      Check the setup, or a Mach-O binary against the SDK or a reference build.
  init        Write wincode.yaml for the Flutter project in this folder.
  preflight   Check the signed IPA and App Store Connect before an upload. Read-only.
  sign        Sign the IPA for the App Store with zsign.
  status      Show the state of the app's latest uploads in App Store Connect. Read-only.
  upload      Upload the signed IPA to App Store Connect and wait for its processing.

Run "wincode help <command>" for more information about a command.
Global options go before or after the command.

Exit codes:
  0   done
  1   failed: a check found a problem, an input is wrong, or Apple or GitHub refused the work
  64  usage error, or not implemented yet
  69  a tool, the SDK or the network is missing
  70  a bug in winCode
  77  Apple or GitHub refused the credentials
  78  wincode.yaml or an environment variable is wrong

$ wincode help doctor
Check the setup, or a Mach-O binary against the SDK or a reference build.

Without options, doctor checks the setup of the app in wincode.yaml and sends nothing: that the file loads, and that the app's App Store Connect key is where its credentials say (a folder with one AuthKey_<Key ID>.p8 and an issuer-id, outside git working trees and OneDrive). To check a binary, give --binary and at least one of --sdk and --reference.

Usage: wincode doctor [arguments]
-h, --help                         Print this usage information.
    --binary=<Mach-O file>         The binary to check, such as Payload/Runner.app/Runner.
    --sdk=<iPhoneOS.sdk folder>    Check the binary against the SDK's text stubs. Fails on a library or binding that its minimum OS lacks.
    --reference=<Mach-O file>      List how the binary differs from a reference build, such as an Xcode-built copy. This does not fail.

Run "wincode help" to see global options.

$ wincode help init
Write wincode.yaml for the Flutter project in this folder.

init reads ios/Runner.xcodeproj for the bundle ID and the entitlements, and the .mobileprovision files of a folder that you name, shows what it found, and asks you to confirm each value. It never writes a key or the key folder (WINCODE_ASC_KEY_DIR), and it never edits .gitignore.

It asks only at a terminal. In CI (the CI variable), with --yes or with --json it asks nothing: give every field as an option, or --yes to accept what it found. Without --force it does not replace a wincode.yaml.

Usage: wincode init [arguments]
-h, --help                    Print this usage information.
    --bundle-id=<id>          The app's bundle ID. Default: read from ios/Runner.xcodeproj.
    --team-id=<id>            The team ID (10 capital letters and digits). Default: from the profile or the Xcode project.
    --profile=<file>          The App Store profile (.mobileprovision). It must lie outside git working trees, or be ignored by git.
    --profile-dir=<folder>    A folder to list the App Store profiles of this app in. Nothing else is searched.
    --entitlements=<file>     The .entitlements file. Default: the one of the Xcode project.
    --workflow-ref=<ref>      The CI workflow for wincode build: <owner>/<repository>/.github/workflows/<file>@<branch or tag>.
    --output=<folder>         Where the IPAs go (default build/wincode).
    --flavor=<name>           Read only the Release-<name> configuration of the Xcode project, the App Store build.
    --configuration=<name>    Read exactly this build configuration of the Xcode project, such as Release-demo, and do not compare Debug and Profile with it.
    --workflow                Copy the reference workflow to .github/workflows/wincode-ios.yml. It never replaces a file.
-y, --yes                     Ask nothing: accept what init found.
    --force                   Replace an existing wincode.yaml.

Run "wincode help" to see global options.

$ wincode help preflight
Check the signed IPA and App Store Connect before an upload. Read-only.

On this PC: the API key and the profile lie outside git working trees, the profile in wincode.yaml, and the IPA (signed.ipa in the output folder by default) with its bundle ID, version, build number and signature. In App Store Connect, with GET requests only: the key works, the app record exists, the build number is above every existing build's, and the App ID has an active App Store profile.

The API key is read from the folder that WINCODE_ASC_KEY_DIR names: AuthKey_<Key ID>.p8 and issuer-id.

Usage: wincode preflight [<signed .ipa>]
-h, --help    Print this usage information.

Run "wincode help" to see global options.

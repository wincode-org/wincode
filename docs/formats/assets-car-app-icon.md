# Assets.car: app icon sample

## A-side observations

Clean-room rule (CONTRIBUTING.md): this file holds what the A side observes in the outputs of Apple's tools, run on Apple hardware. It never looks inside the tools themselves. The B side writes winCode's `Assets.car` compiler from this file only.

### The sample

- **Input:** `Sample.xcassets` with one app icon set, `AppIcon.appiconset`, in Xcode's single-size format: one 1024 × 1024 image, idiom `universal`, platform `ios`.
- **Image:** `icon-1024.png`, generated by the workflow itself: 8-bit RGB, no alpha, a plain gradient (red follows x, green follows y, blue fixed at 128). No Apple, client or brand art, and no text.
- **Compiler:** `actool` from Xcode 26.6 on GitHub's `macos-26` runner, run by `.github/workflows/oracle-reference-builds.yml` (step "Icon sample"):

  ```
  xcrun actool Sample.xcassets --compile compiled --platform iphoneos --minimum-deployment-target 15.0 \
    --target-device iphone --target-device ipad --app-icon AppIcon \
    --output-partial-info-plist compiled/partial-Info.plist \
    --output-format human-readable-text --notices --warnings --errors
  ```

- **Recorded** (artifact `icon-sample`, kept 7 days):
  - `compiled/Assets.car`
  - `compiled/partial-Info.plist`
  - `assetutil-info.json` (`xcrun assetutil --info compiled/Assets.car`)
  - `actool-output.txt`
  - `compiled-files.txt`: every file actool wrote
  - `actool-command.txt`
  - the input catalog itself
- **For comparison:** the run also saves the `actool` invocations Xcode itself makes while building the two Flutter test apps (artifact `xcode-dumps`, `xcode-actool-invocations.txt`). Those apps' icons are Flutter's template artwork, so their `Assets.car` files are not used for this spec.

# Assets.car: launch colour and launch image sample

## A-side observations

Clean-room rule (CONTRIBUTING.md): this file holds what the A side observes in the outputs of Apple's tools, run on Apple hardware. It never looks inside the tools themselves. The B side writes winCode's `Assets.car` compiler from this file only. This file adds to `assets-car-app-icon.md`; the app icon facts are not repeated here.

### The sample

- **Input:** the `Sample.xcassets` of `assets-car-app-icon.md` (the `AppIcon.appiconset` is unchanged) plus two more sets, and a separate `UILaunchScreen.plist` that names them. All of it is generated by the workflow itself. No Apple, client or brand art, and no text.
  - `LaunchBackground.colorset/Contents.json` (180 bytes): one colour, idiom `universal`, colour space `srgb`, components red `0.200`, green `0.400`, blue `0.600`, alpha `1.000` (written as strings).
  - `LaunchImage.imageset/Contents.json` (237 bytes): three images, idiom `universal`, scales `1x`, `2x`, `3x`, files `launch@1x.png`, `launch@2x.png`, `launch@3x.png`.
  - The three PNGs are 8-bit RGBA (colour type 6) squares of 64, 128 and 192 px, 298, 647 and 1160 bytes. Read from the first row of each: the first pixel is (32, 96, 160, 0) and the last is (32, 96, 160, 255), so red, green and blue are the same at both ends and alpha goes from 0 to 255.
  - `UILaunchScreen.plist` (330 bytes): `UILaunchScreen` → `UIColorName` = `LaunchBackground`, `UIImageName` = `LaunchImage`. `plutil -lint` printed `OK` in the run log. actool is not given this file.
- **Compiler:** `actool` from Xcode 26.6 on GitHub's `macos-26` runner, run by `.github/workflows/oracle-reference-builds.yml` (step "Icon sample (placeholder icon, launch colour and launch image, compiled by actool)"). The command line is the one in `assets-car-app-icon.md`, byte for byte (`actool-command.txt` of both runs is identical).
- **Recorded** (artifact `icon-sample`, kept 7 days): the same files as for the app icon, plus the three PNGs, the two `Contents.json` files and `UILaunchScreen.plist` of the input catalog.

### Commands that reproduce the observations

```
# On a Mac with Xcode 26.6 (or by running the workflow):
gh workflow run oracle-reference-builds.yml --ref main
gh run download <run id> -n icon-sample

# What the workflow runs on the catalog (the command line is unchanged from the app icon sample):
xcrun actool Sample.xcassets --compile compiled --platform iphoneos --minimum-deployment-target 15.0 \
  --target-device iphone --target-device ipad --app-icon AppIcon \
  --output-partial-info-plist compiled/partial-Info.plist \
  --output-format human-readable-text --notices --warnings --errors
xcrun assetutil --info compiled/Assets.car > assetutil-info.json
plutil -lint UILaunchScreen.plist

# On any machine, from the downloaded artifact:
head -c 8 compiled/Assets.car
grep -abo -e AppIcon -e LaunchBackground -e LaunchImage -e 'launch@' -e 'icon-1024.png' \
  -e colorset -e imageset compiled/Assets.car
```

### Observations

Run 40176056812 (2026-10-25, `main` at commit 0e35f78, all steps succeeded, run time 2 min 18 s) on `macos-26`: macOS 26.6.2 (25G83), Xcode 26.6 (17F113), iphoneos SDK 26.5, `actool` 26.6 (bundle version 24765). These are the same versions as run 39513689791. Every fact below comes from this run's `icon-sample` and `xcode-dumps` artifacts.

**Unchanged from run 39513689791:** the icon source `icon-1024.png` (119,236 bytes, same SHA-256), the two loose icon PNGs (`AppIcon60x60@2x.png` 679 bytes, `AppIcon76x76@2x~ipad.png` 938 bytes, same SHA-256), `partial-Info.plist` (713 bytes, same SHA-256), `actool-output.txt` (303 bytes, same SHA-256), `actool-command.txt`, and every header field of `assetutil --info` except `Timestamp`. The four app icon entries (two "Icon Image", two "MultiSized Image") are identical, field for field, including `NameIdentifier` 6849 and the digests. The `Assets.car` files that Xcode itself builds for the two Flutter test apps are the same size as before (66,920 bytes each), and `xcode-actool-invocations.txt` is identical.

**Changed:** `Assets.car` grew from 170,040 to 173,032 bytes (+2,992). `assetutil --info` lists 8 entries after the header, up from 4: the four app icon entries plus one colour entry and three image entries. The `SizeOnDisk` values of the four new entries add up to 2,557. `Timestamp` is 1792916400 (2026-10-25 08:20:00 UTC; the job ran 08:17:55 to 08:20:10 UTC). In run 39513689791 it was 1792538210 (2026-10-20 23:16:50 UTC).

- The idiom stays `universal`; actool does not split it into `phone` and `pad`, unlike the app icon.

### Not yet known

- Whether iOS finds the colour and the image through `UILaunchScreen`. No app, simulator or device has been run with this catalog.
- How `NameIdentifier` is computed (995, 6849 and 36251 for these three names), and what the 64-digit `SHA1Digest` is a digest of.
- How `Assets.car` is laid out: where the entries, their keys (the `Key Format` fields: element, part, identifier and the others) and their data sit. `assetutil` does not print the element and part values.
- Where the 435 bytes of growth beyond the new entries' `SizeOnDisk` (2,992 − 2,557) are used.
- What deepmap2 is, how the pixels are stored in it, and whether they are premultiplied by alpha. The 64 px image takes more bytes on disk than its PNG (627 against 298); the 192 px image takes fewer (927 against 1160).
- Whether the colour components are 32-bit floats in the file or only appear so in `assetutil`'s output.
- What changes with other inputs: a colour set with dark or high-contrast appearances, display P3 or gray colours, a colour set with several idioms, image sets with only one scale or with `iphone` and `ipad` idioms, PDF or SVG images, a template rendering intent, and 16-bit or indexed PNGs.
- What changes with other flags: Xcode's own invocation adds `--compress-pngs`, `--enable-on-demand-resources`, `--bundle-identifier` and others (see `assets-car-app-icon.md`). Whether any of them changes the output for these two sets, or makes actool write launch keys into the partial plist, is unknown.
- Why `Timestamp` is a whole minute in this run and not in run 39513689791, and what it is derived from.
